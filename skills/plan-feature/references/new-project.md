# Plan a new project

1. Start a `plan` session in the configured planning workspace. If the expected checkout path is known, start in a directory that contains it or has permission to move there. Agree on who the project is for, what the first usable version does, and one concrete user flow. Run the required `domain-modeling` step and keep the proposed glossary and ADRs in the plan while the project has no repository.
2. Use those decisions to propose a repository name, toolchain, license, and visibility. When the user approves setup, pass the agreed setup to `init-project` in a write-capable run. Relay any provisioning approval requested by `init-project` and wait for its repository and checkout to be ready.
3. When `init-project` returns the absolute checkout path, move the original `plan` session there with OpenCode's built-in tool. Call `tools.opencode.session.move({ directory: checkoutPath })` through Code Mode's `execute`, or call `opencode_session_move` with the same directory when tools are exposed directly. Omit `sessionID` so the tool moves the current session.
4. Let the move take effect before working in the checkout. Confirm the working directory in the same session, then check the proposed acceptance commands against the scaffold. If the move fails, including a denied `external_directory` permission, return the error, goal, terms, agreed decisions, and open questions so the caller can start a fresh `plan` session in the checkout.

Return to the Issue-drafting steps in `plan-feature` with the repository URL, decisions, and the agreed scope of the first usable version. Draft Issues for that whole scope; it can take an Epic with several sub-issues.

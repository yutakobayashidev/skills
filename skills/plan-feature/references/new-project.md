# Plan a new project

1. Use the planning session's working directory as the base for the move. When opening a session for a new repository, choose the parent directory where `init-project` will create the checkout. In an existing session, confirm its working directory before requesting a move. Agree on who the project is for, what the first usable version does, and one concrete user flow. Run the required `domain-modeling` step and keep the proposed glossary and ADRs in the plan while the project has no repository.
2. Use those decisions to propose a repository name, toolchain, license, and visibility. When the user approves setup, pass the agreed setup to `init-project` in a write-capable run. Relay any provisioning approval requested by `init-project` and wait for its repository and checkout to be ready.
3. When `init-project` returns the absolute checkout path, move the original `plan` session there with OpenCode's built-in tool. In Code Mode, use the session move tool at the path listed in the tool catalog. When tools are exposed directly, call `opencode_session_move`. Pass the checkout path as `directory` and omit `sessionID` to move the current session.
4. Let the move take effect before working in the checkout. Confirm the working directory in the same session, then check the proposed acceptance commands against the scaffold. If the move fails, including a denied `external_directory` permission, return the error and this session's ID so the caller can start a fresh `plan` session in the checkout. That session reads this one with `handoff_read`: `context` mode first, then `messages` for the user's decisions and constraints that compaction may have dropped.

Return to the requirements steps in `plan-feature` with the repository URL, earlier decisions, and the scope of the first usable version. Confirm its behavior and acceptance criteria before decomposing the whole agreed scope.
